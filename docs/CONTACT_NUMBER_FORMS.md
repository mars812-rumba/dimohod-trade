# Контакты по номеру — 2026-11-23

По запросу владельца во всех публичных формах доступны только телефон,
MAX и WhatsApp. Имя и остальные существующие поля сохраняют свои правила;
быстрый расчёт и готовые комплекты по-прежнему принимают контакт без имени.

`PhoneContactFields.tsx` задаёт единый список каналов, подпись номера,
`type="tel"`, цифровую клавиатуру и автозаполнение. На экранах до 480 px
поля идут друг под другом. В тёмном контактном блоке главной подписи и
ошибки имеют светлый цвет.

Формы `LeadForm`, `QuickEstimateContactForm`, `EstimateLeadDialog`
(включая встроенную форму) и `ReadyKitContactForm` передают `contact_method`
и `contact`. Общая клиентская проверка и сервер принимают только три канала
и номер из 7–15 цифр; разрешены плюс, пробелы, скобки и дефисы.
Новые Telegram/email-заявки сервер отклоняет до сохранения и уведомлений.
Номер сохраняется также в существующем поле `phone` для всех трёх каналов.

MAX добавлен в типы смет, CRM, письмо менеджеру и накладную. Телефон/MAX/
WhatsApp с одинаковым номером относятся к одному клиенту. Для MAX в CRM
показывается название канала и номер с обычной ссылкой звонка; неподтверждённые
deep links не используются. Старые Telegram/email-контакты и документы
продолжают читаться. Миграция, изменения БД и storage не требуются.

Проверки:

- 95 backend-тестов: `test_leads.py`, `test_quick_estimate_contact.py`,
  `test_ready_kits.py`, `test_customers.py`, `test_lead_email.py`.
- 35 frontend-тестов: общие поля, проверка номера и сохранённого ответа,
  отправка смет, сценарные страницы, готовые комплекты и накладная.
- Production-сборка Next.js с проверкой TypeScript.
- `tools/check_phone_contact_forms_browser.cjs`: четыре настоящие формы,
  переключение всех трёх каналов, отказ для `@username`, сохранение контакта
  и номера, ширина 360/1440 px. Изолированный API
  `tests.contact_forms_preview` пишет только в `/tmp/dimohod-*`, использует
  тестовый состав комплектов, отключает SMTP и доступ к БД; каталог для
  расчёта получает только публичными GET. Рабочая CRM не затрагивается.

Production deploy и commit в этой задаче не выполняются. Публикация —
отдельной командой Telegram-бота через штатный native pipeline.
