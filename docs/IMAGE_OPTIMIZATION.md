# Оптимизация фотографий каталога

Новые фотографии, загруженные через админку, автоматически сохраняются в двух файлах:

- основной WebP — не более `1200 × 1200`, качество 80;
- миниатюра `*.thumb.webp` — не более `480 × 480`, качество 72.

Исходный JPEG/PNG при новой загрузке не сохраняется. В данных фотографии записываются URL
обоих вариантов, размеры основного изображения и SHA-256. Ограничение входного файла — 8 МБ.

## Обработка уже загруженных фотографий

Команды выполняются из каталога `backend` после установки зависимостей проекта.

```bash
python -m app.scripts.optimize_catalog_media audit --storage ../storage
python -m app.scripts.optimize_catalog_media convert --storage ../storage
python -m app.scripts.optimize_catalog_media apply --storage ../storage
python -m app.scripts.optimize_catalog_media apply --storage ../storage --commit
```

Порядок безопасного запуска:

1. `audit` только читает изображения и формирует отчёт.
2. `convert` создаёт WebP и миниатюры рядом с исходниками, не удаляя исходники.
3. `apply` создаёт резервную копию JSON-полей БД и показывает число замен, но откатывает
   транзакцию без `--commit`.
4. Только после проверки отчёта запуск с `--commit` переключает БД на новые URL.

Отчёты и резервные копии по умолчанию создаются в каталоге `backups`. Исходники скрипт не
удаляет ни в одном режиме.
