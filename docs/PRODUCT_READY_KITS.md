# Готовые комплекты для выбранного SKU — 2026-11-22

В карточке изделия после «Параметров выбранного варианта» и перед
«Расчёт комплекта» добавлен компактный блок «Входит в готовые комплекты».
Иконка — `Package` из `lucide-react`. При отсутствии совпадений весь блок скрыт.

## Данные и точное сопоставление

Серверная страница товара один раз получает `GET /api/v1/ready-kits`
с `cache: no-store`. Это существующий публичный список: backend уже учитывает
публикацию, согласование, runtime-правки составов и доступность SKU.
Новые таблицы, сохранённые соответствия и отдельный endpoint не добавляются.

`productReadyKitMemberships` использует все опубликованные комплекты и передаёт
клиенту только адрес, подпись и уникальные `line.sku_id` каждой спецификации.
Именно этот SKU используется существующей строкой `ReadyKitLineDetails`
при формировании ссылки на конкретное исполнение изделия.

`ProductExperience` на каждом рендере сопоставляет `activeSku.id` с этими ID.
Диаметр, семейство, артикул и название изделия не участвуют в поиске.
Ограничений по числу комплектов и диаметрам нет. Один вариант комплекта
показывается один раз, даже при повторении SKU в нескольких строках BOM.
Маршрут/высота/диаметр для подписи берутся из ответа, адрес — из `kit.slug`
через существующий `kitPath`; для названия маршрута используется
`recommendationName`, общий с рекомендациями комплектов.

Начальные ссылки присутствуют в серверном HTML выбранного SKU, включая
прямой переход из спецификации по артикулу. При переключении исполнения
список пересчитывается синхронно из того же компактного набора, без запросов
комплектов из браузера и без ожидания подробных параметров/совместимости SKU.
У новых ссылок отключён `prefetch`. Ошибка получения комплектов скрывает
только этот необязательный блок, без устаревших seed-данных и ошибки товара.

## Проверки на реальных публичных данных

- `DT-GOLYE-09-11-D115`, ID `ebe5ab1c-a25f-422a-879a-197c69606c3f`:
  четыре комплекта Ø115; переход AISI 304 → AISI 430 при том же диаметре
  скрывает блок, обратный выбор восстанавливает; Ø120 меняет адреса ссылок.
- `DT-PASSAGE-GLASS-GALV-D100-200`, ID `767e3b91-c393-5e51-932c-cd5ed853c70e`:
  один общий SKU с `diameter_mm=null` присутствует во всех 12 комплектах.
  Ссылки сохраняют разные диаметры и ведут на соответствующие варианты,
  в чьих спецификациях есть тот же артикул/SKU.

Автоматизация: `productReadyKits.test.mjs`, проверки серверного рендера и
производительности товара; браузер — `tools/check_product_ready_kits_browser.cjs`.
Изолированный `tools/product_ready_kits_preview.py` разрешает только GET
к публичным данным и media, хранит снимки в памяти и считает обращения.
Админка, БД, отправка форм и production-изменения не используются.
Next.js собирается с `API_BASE_URL=http://127.0.0.1:8129` и отдельным
`NEXT_DIST_DIR`; Chromium запускается с loopback `READY_KITS_BASE_URL`.

Результат: 16 целевых тестов и production-сборка с TypeScript прошли.
На реальных данных подтверждены все три случая выше, включая отсутствие
блока в SSR для AISI 430, его скрытие/возврат при смене стали и обновление
ссылок при Ø115 → Ø120. На 320/390/1440 px нет переполнения, ссылки имеют
область нажатия от 44 px; все 12 ссылок общего SKU доступны без JS.
Проверен реальный переход на комплект каждого из трёх диаметров с тем же
SKU в спецификации. На SSR приходится один запрос общего списка,
браузер не выполняет запросов комплектов. Скриншоты:
`.codex-telegram/product-ready-kits/shared-*.png`.

Публикация — отдельной штатной командой Telegram-бота. SEO-метаданные,
совместимость, цены, составы комплектов, PDF и CRM не меняются.

## Проверка сэндвичей и расширение линейки — 2026-11-22

На работающем сайте прямой переход по артикулу из BOM уже возвращает нужные
ссылки в серверном HTML. При открытии только семейства/диаметра выбран другой SKU:

- Сэндвич-труба Ø115/215: начальный `DT-SW50-01-00-D115-215` отсутствует
  в спецификациях. `DT-SW50-19-00-D115-215` входит в два Roof-комплекта,
  `DT-SW50-17-00-D115-215` — в четыре комплекта этого диаметра.
- Дефлектор-конус Ø115/215: начальный `DT-SW50-03-15-D115-215` отсутствует
  в спецификациях, `DT-SW50-17-15-D115-215` входит в четыре комплекта.

Автоматически заменять начальный SKU или показывать ссылки другого исполнения
нельзя: блок по-прежнему отражает только точный ID выбранного SKU.

Снята прежняя фильтрация комплектов Ø115/120/150. Результат следует всему
публичному списку без лимита 12. `getReadyKit` принимает безопасный человекочитаемый
slug, а существование/публикацию проверяет API; высоты и диаметры не перечислены
в регулярном выражении frontend или `Literal` backend.

Перечень доступных моделей теперь задаёт `backend/app/modules/ready_kits/lineup.json`,
а не вложенные циклы по фиксированным высотам и диаметрам. В реестре остаются
только 12 существующих вариантов с прежними URL и порядком. Это реестр моделей,
не таблица соответствий деталей: составы и точные связи SKU берутся из прежних
спецификаций. Для расширения добавляется запись `{slug, route, height_m, diameter_mm}`;
новый вариант без согласованного состава появляется в существующей админке как
неопубликованный черновик. Затем состав заполняется и согласовывается штатным
редактором; проверки активных SKU и публикации сохраняются. Совпадение размеров
новой модели с прежней само по себе не переносит старое согласование.
Существующие runtime-файлы имеют прежний приоритет; повреждённый реестр,
повторный slug или повреждённый runtime-файл завершаются ошибкой без подмены seed.
Изменение реестра исходников публикуется отдельным релизом. Формы создания модели
в админке эта доработка не добавляет. Новых реальных составов и SKU не создавали.

Проверки после доработки:

- 58 backend-тестов: все прежние составы/публикации, добавление тестового 13-го
  варианта 8 м / Ø180, его начальная скрытость и явная публикация, ошибки реестра
  и отсутствие наследования согласования другой моделью.
- 27 frontend-тестов: более 12 вариантов, новый диаметр, новые URL,
  точное сопоставление/скрытие, SSR и существующие контракты товара/комплектов.
- Production-сборка Next.js и TypeScript прошла.
- Изолированный Chromium на реальных публичных данных: все 15 уникальных SKU
  сэндвич-трубы и дефлектора-конуса из текущих спецификаций имеют точные ссылки
  в HTTP HTML и после загрузки страницы; смена стали скрывает/возвращает блок,
  смена толщины и длины трубы меняет правильные наборы комплектов.
  Подтверждено отсутствие блока для начальных SKU обоих семейств. Сохранены
  проверки общего SKU в разных диаметрах, без JS, 320/390/1440 px и отсутствия
  браузерных запросов к API комплектов. Число ожидаемых ссылок берётся из ответа,
  а не задаётся константой 12. Production, БД и storage не менялись.
