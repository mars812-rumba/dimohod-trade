Проверены все уникальные URL из выгрузки: последнее событие Яндекса, текущий HTTP-ответ production, серверный HTML, canonical, sitemap, внутренние ссылки категорий и production-БД. Проверка выполнялась без изменения маршрутов, карточек и данных.

## Итог

- В исходном CSV 826 событий для 424 уникальных URL. Один адрес может иметь несколько последовательных `ADD`/`DELETE`, поэтому итог определялся по самой свежей строке адреса.
- Все 424 URL на момент проверки отвечают HTTP 200.
- 210 из 387 товарных URL — полноценные рабочие карточки: есть H1, self-canonical, Product JSON-LD и цена выбранного SKU. 202 диаметральные карточки содержат диаметр в H1.
- 177 товарных URL — подтверждённые soft 404: HTTP 200, но HTML содержит `Товар не найден`, `noindex`, без H1 и canonical. Все эти адреса отсутствуют в sitemap.
- Все 177 soft-404 URL однозначно сопоставлены с активными семействами и активными диаметрами production-БД. Они охватывают 2 175 активных SKU; у всех 2 175 есть положительная цена. Это не переименованные и не снятые товары.
- Причина исключения по текущему коду публикации: 162 URL не имеют применимого изображения; 15 URL семейства `odnostennyy-reviziya-prochistka` не имеют применимого изображения и эффективного описания.
- Ни одного доказанного переезда на новый slug, окончательно удалённого товара или ошибочного товарного адреса в этой выгрузке не найдено. Поэтому список безопасных 301-редиректов сейчас пуст.
- В sitemap находятся 210 рабочих товарных URL из CSV. Ещё две рабочие карточки sitemap отсутствуют в этой выгрузке: `odnostennyi-otvod-90-gr-d120` и `sendvich-opornaya-ploschadka-d160-260`.

## Внутренние ссылки категорий

- 202 рабочих диаметральных URL имеют прямые ссылки из серверного HTML категорий.
- Ещё 8 рабочих семейств без диаметра связаны из категорий только URL с `?sku=...`; их canonical ведёт на чистый адрес без параметров. Для более ясной внутренней структуры стоит дать категории ссылку на canonical URL, а выбор SKU выполнять уже внутри карточки.

## Проверка содержимого рабочих карточек

Из 210 рабочих товарных страниц:

- 210 имеют H1 и self-canonical;
- 210 имеют Product JSON-LD с URL выбранной карточки и положительной ценой;
- у 206 выбранный материал присутствует в Product JSON-LD;
- у 4 недиаметральных изделий материал в JSON-LD пуст: `konsol-teleskopicheskaya`, `konsol-universalnaya`, `master-flesh`, `komplekt-vaty-dlya-prohodnogo-stakana`. Это нужно сверить с фактическими полями товара, не заполняя материал предположением.

## Что исправлять следующим

1. Исправить soft 404: URL с отсутствующим публичным SKU не должен возвращать HTTP 200 со страницей `Товар не найден`.
2. Активный товар с подтверждёнными данными публиковать независимо от наличия фото и рекламного описания. Для отсутствующего фото показывать нейтральную заглушку, а неполноту контента отмечать менеджеру в админке. Фото семейства использовать только в области тех вариантов, для которых оно задано.
3. Если отдельный товар действительно решено снять, вернуть настоящий 404 или 410. Не перенаправлять такие адреса массово на каталог.
4. Сделать восемь ссылок категорий на недиаметральные семейства каноническими URL без `?sku=...` либо добавить рядом отдельную доступную поисковику canonical-ссылку.
5. После выкладки повторить обход этих 177 URL и запросить переобход в Яндекс Вебмастере. `LOW_DEMAND` у 197 уже рабочих карточек анализировать отдельно: сопоставить дату последнего обхода с датой исправлений и определить, какую версию видел робот. Текущая исправность страницы не объясняет автоматически её прежний статус.
