# Карточки товара: видимый серверный HTML

## Изменение

Убрана автоматическая граница загрузки `app/product/[slug]/loading.tsx`.
Раньше готовая карточка попадала в скрытый потоковый блок, раскрываемый JavaScript;
при отключённом JavaScript оставался экран «Загружаем товар…».
Теперь сервер дожидается данных и отдаёт видимый основной контент карточки.

Сервер также запрашивает существующие комплектующие для **выбранного SKU**
через действующий API совместимости. Их цены не кешируются этим запросом.
При ошибке запроса комплектующих остаётся основной товар, а браузер может
повторить запрос существующим клиентским механизмом.

Не менялись URL, canonical, правила robots, цены, совместимость, расчёты,
SEO-тексты и обработка заявок. Существовавшие изменения в рабочем дереве сохранены.

## Проверка

Изолированная production-сборка Next.js прошла. Остались прежние предупреждения
autoprefixer о `start`/`end` в CSS админки и глобальных стилях; ошибок сборки нет.
41 тест `product*.test.mjs` прошёл, включая два новых регрессионных теста.

Локальная собранная версия проверена Chromium с JavaScript и без него:

| Карточка | Видимый H1 без JS | Ссылки на товары без JS |
| --- | --- | --- |
| `/product/odnostennyi-truba-d110` | Одноконтурная труба 110 мм | 2 |
| `/product/sendvich-opornaya-ploschadka-d110-210` | Сэндвич-опорная площадка 110/210 мм | 3 |
| `/product/odnostennyi-truba-d150` | Одноконтурная труба 150 мм | 2 |

Во всех случаях HTTP 200, один видимый H1, JSON-LD читается, экран загрузки
не остаётся. Для трубы 110 мм цена, canonical, robots и ссылки совпадают
до и после гидратации. Переключение исполнения и добавление в локальную
корзину работают. Несуществующий товар возвращает HTTP 404.
Ошибок JavaScript на трёх проверенных карточках не обнаружено.
Запросы Метрики в браузерных проверках блокировались; заявки и заказы не отправлялись.

## Почему не весь сайт на статике

Статическая сборка и видимый серверный HTML — не одно и то же.
Для устранения найденной зависимости достаточно SSR без границы загрузки
вокруг основного товара. Это сохраняет свежие данные API и интерактивность.
В сборке уже есть статические информационные страницы, статьи и сценарии;
карточки и каталог остаются серверными по запросу.
Полная статическая генерация потребует отдельно решить обновление цен,
доступности и новых исполнений. Этот объём сейчас не выполнялся.

Компромисс: ответ карточки ждёт запросы товара и комплектующих, вместо
мгновенного показа скелетона. Измеренные локальные времена браузерной
проверки не являются оценкой production TTFB или обещанием PageSpeed.

## После публикации владельцем

1. Повторить проверку видимости без JS на production.
2. Сравнить сохранённое представление карточки в Яндекс Вебмастере.
3. С согласия владельца отправить контрольные URL на переобход.
4. Отслеживать возвращение карточек в поиск и небрендовые показы.

Найденный риск рендеринга устранён локально, но причинная связь с LOW_QUALITY
и рост позиций пока не доказаны. Публикация и переобход не выполнялись.

Механизм автоматической границы загрузки описан в
[документации Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/loading).
