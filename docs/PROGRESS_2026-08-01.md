# Прогресс Dimohod Trade на 2026-08-01

Этот документ фиксирует текущее подтверждённое состояние каталога после переработки карточек,
SEO-генератора, совместимых изделий и производительности. Короткие приоритеты остаются в
`NEXT_STEPS.md`, а этот файл хранит технические детали выполненного этапа.

## Каталог и карточка семейства

- `Product` остаётся товарным семейством, `SKU` — конкретным вариантом.
- Общий каталог используется как навигатор по компактным карточкам категорий.
- Страница категории содержит поиск и фильтры по диаметру, марке стали и виду материала.
- В карточке семейства материал выбирается кнопками «Нержавейка / Оцинковка».
- Диаметр и марка стали выбираются списками, остальные доступные параметры строятся из реальных SKU.
- Цена, артикул, наличие, характеристики, metadata и JSON-LD относятся к выбранному SKU.
- Трубы с одинаковыми основными параметрами показываются одной карточкой совместимого семейства;
  доступные длины переключаются внутри карточки.
- Блок «Расчёт комплекта» выделен в самостоятельную акцентную панель после описания и параметров:
  иконка калькулятора, короткое пояснение и кнопка «Рассчитать комплект» ведут в конфигуратор.
  На мобильном кнопка занимает всю ширину блока.

## SEO

- В админке есть редактируемые поля короткого описания, основного описания, SEO title и meta description.
- Кнопка «Сгенерировать SEO» сначала собирает подтверждённый пакет фактов, затем создаёт черновик
  строго на его основе. Автоматической публикации нет.
- Семейный текст отделён от динамических характеристик выбранного SKU.
- Изменяемые параметры title и meta description хранятся через поддерживаемые переменные, а не
  захардкоженные диаметры другого варианта.
- Диапазоны семейства вычисляются по активным SKU и не хранятся вручную.
- Постоянные правила достоверности и естественного языка находятся в
  `skills/chimney-product-seo/SKILL.md`.
- Неподтверждённые температуры, нормы, монтажные расстояния, сертификаты и требования пожарной
  безопасности генератор добавлять не должен.

## Совместимые изделия

- В карточке показываются только семейства, выбранные для совместимости в админке и прошедшие
  фактическую проверку параметров выбранного SKU.
- Для сэндвич-труб проверяются внутренний и наружный диаметры, толщина изоляции, марка и вид стали,
  а длина остаётся выбираемым вариантом.
- Для крепежа сопоставление выполняется по наружному диаметру сэндвич-элемента; например, для
  исполнения 250/350 допустим хомут 350 мм, а хомут 250 мм отклоняется. Заполненные материал и
  марка стали дополнительно должны совпадать.
- Сервер сохраняет привязку к совместимому семейству, а не копирует все его SKU в настройки товара.

## Ускорение карточек

Ранее карточка большого семейства могла проверять кандидатов совместимости против каждого из 1584 SKU
в Python. Это создавало вложенный перебор и задерживало ответ API.

Выполнено:

1. `GET /api/v1/products/{slug}` принимает выбранный `sku` и рассчитывает совместимость только для него.
2. Предварительная фильтрация совместимых труб и крепежа перенесена в SQL.
3. Добавлен endpoint `GET /api/v1/products/{slug}/compatible?sku=...` для переключения варианта без
   повторного получения всей карточки.
4. Frontend загружает совместимые изделия по выбранному SKU и хранит результат в клиентском кэше.
5. Добавлена миграция `202608010002_sku_matching_indexes.py`:
   - `ix_skus_active_tube_match` для активных вариантов труб;
   - `ix_skus_active_fastener_match` для активных вариантов крепежа, включая наружный диаметр.
6. Серверная загрузка карточки по-прежнему использует кэш Next.js с `revalidate: 60`.

После применения изменений пользователь подтвердил: ошибка исчезла.

## Проверки этапа

- Production-сборка Next.js прошла успешно.
- Изменённые Python-файлы прошли `py_compile`.
- `git diff --check` не обнаружил ошибок форматирования патча.
- Полный запуск backend pytest в локальном окружении не состоялся из-за отсутствующего пакета
  `SQLAlchemy`; это ограничение окружения, а не успешный результат тестов.

## Что делать дальше

1. Применять миграцию индексов на каждом окружении командой `alembic upgrade head` через штатный
   процесс деплоя.
2. Замерить время ответа карточки и endpoint совместимости на production после прогрева кэша.
3. Если семейство из 1584 SKU всё ещё даёт большой ответ, добавить компактный endpoint доступных
   значений и загружать только выбранный SKU и соседние варианты.
4. Статическую генерацию популярных карточек рассматривать после измерений; она не заменяет индексы
   и оптимизацию SQL.
