# Прогресс Dimohod Trade на 2026-08-03

Этот документ фиксирует актуальное подтверждённое состояние каталога, карточки товара,
вариантов SKU, фотографий и совместимых изделий. Отчёт
`docs/PROGRESS_2026-08-01.md` остаётся историей предыдущего этапа.

## Каталог и карточка товара

- `Product` остаётся товарным семейством, `SKU` — конкретным исполнением.
- Каталог и карточка товара приведены к общей визуальной системе главной страницы.
- В каталоге используются динамические фильтры по фактически доступным полям SKU.
- Базовый порядок выбора: диаметр, вид материала, марка стали и остальные параметры,
  существующие у изделий выбранной категории.
- Карточка и её характеристики строятся из выбранного SKU, а не из захардкоженного варианта.
- Публичные запросы каталога и карточки не используют устаревающий Next.js-кэш: изменения,
  сохранённые через админку, должны читаться из backend при следующем запросе.

## Материал и варианты SKU

- Вид материала хранится отдельно от марки стали: нержавейка и оцинковка являются разными
  визуальными исполнениями.
- Марки нержавеющей стали используют одну визуальную галерею, если редактор явно не задал
  более узкое правило фотографии.
- Длина изделия разделяет визуальные исполнения труб.
- Диаметр по умолчанию не разделяет галерею. Для исключений у фотографии есть признак
  `diameter_specific` — «Только для выбранного диаметра d/D».

## Фотографии семейства и SKU

- У семейства и конкретного SKU доступны три роли: общий вид, вид сверху и порты/соединение.
- Если у SKU нет подходящего фото, используется соответствующее фото семейства.
- Базовая область действия фото SKU: семейство + вид материала + длина, независимо от марки
  нержавеющей стали и диаметра.
- Фото с `diameter_specific=true` применяется только при совпадении d/D и имеет приоритет
  над общим фото исполнения.
- Старые фотографии без нового признака считаются общими для всех диаметров своего материала
  и длины; миграция БД для этого не требуется.
- При наличии нескольких подходящих файлов выбирается самая свежая версия URL изображения.
- Кнопка «Сохранить фото» сначала автоматически сохраняет текущие структурированные параметры
  выбранного SKU, затем загружает фотографии.
- После загрузки админка повторно читает SKU из базы, проверяет URL файла и показывает alert
  со статусами сохранения SKU, загрузки и выдачи медиа.

## Совместимые изделия

- Администратор задаёт разрешённые товарные семейства вручную.
- Backend больше не отбрасывает выбранные шиберы, оголовки и другие типы только потому, что
  они не являются трубами или крепежом.
- Внутри разрешённого семейства выбираются активные SKU по заполненным фактическим параметрам:
  присоединительному диаметру и, когда значения присутствуют с обеих сторон, наружному диаметру,
  утеплению, материалу, марке стали и контуру.
- Endpoint совместимости и клиентский запрос работают без кэша, чтобы сохранённые изменения
  были видны при следующем открытии карточки.

## Проверки контрольной точки

- Production-сборка Next.js проходит успешно после изменений интерфейса и логики медиа.
- Изменённые Python-файлы успешно проходят `compileall`.
- `git diff --check` не обнаруживает ошибок форматирования патча.
- Добавлены тестовые сценарии для общей фотографии между разными диаметрами и для приоритета
  диаметрального исключения.
- Полный локальный запуск backend pytest по-прежнему недоступен в оболочке без SQLAlchemy;
  штатная команда `/ship` запускает backend-тесты в Docker перед commit, push и deploy.

## Следующий практический шаг

1. Выполнить штатный `/ship` и пересобрать backend и web.
2. На production проверить одну нержавеющую и одну оцинкованную трубу одинаковой длины на разных
   диаметрах: общее фото должно наследоваться, а диаметральное — переопределять его только для d/D.
3. Проверить вывод выбранных в админке совместимых семейств на карточке конкретного SKU.
4. После подтверждения сценария масштабировать заполнение галерей на остальные семейства изделий.
