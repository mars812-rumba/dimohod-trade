# Области применения фотографий семейства и SKU — 2026-08-08

## Задача

Настройки фотографий разделены по смыслу:

- базовые фотографии семейства содержат по одному общему файлу ролей `general`, `top` и `connection`;
- фотографии вариантов загружаются из блока выбранной модели, но могут применяться к нескольким
  отмеченным диаметрам d/D и длинам;
- режим «Только для выбранного SKU» создаёт точное фото одной модели.

Например, фото варианта можно назначить диаметру `200/300` и длинам `500, 1000 мм`. Оно будет
использоваться у исполнений `200/300 × L500` и `200/300 × L1000`, но не у других сочетаний.

## Правила применения

Для фотографий вариантов ограничения диаметра и длины работают как пересечение:

| Диаметр | Выбранные длины | Где показывается фото |
|---|---|---|
| Не выбран | Не выбрана | Все активные SKU семейства |
| Не выбран | 500, 1000 мм | Все диаметры с длиной 500 или 1000 мм |
| 200/300 | Не выбрана | Все длины диаметра 200/300 |
| 200/300 | 500, 1000 мм | Только пересечение выбранного d/D и длин |

- варианты d/D и длины берутся из активных SKU товарного семейства;
- пустой набор одного параметра означает «все», но хотя бы диаметр или длина должны быть выбраны;
- область уже сохранённого фото варианта можно изменить без повторной загрузки файла;
- внутри роли вариантов можно хранить несколько фотографий с разными областями применения: добавление
  нового `general`, `top` или `connection` больше не заменяет остальные фотографии этой роли;
- верхний блок семейства всегда содержит не больше одного базового файла каждой роли и не показывает
  параметры SKU;
- подходящее фото выбирается по специфичности: `диаметр + длина` → `диаметр` или `длина` → общее;
- если подходят несколько фотографий одинаковой специфичности, используется добавленная последней;
- точные повторы старых записей схлопываются при чтении; повторная загрузка одного и того же файла
  той же роли определяется по SHA-256 и объединяет выбранные области вместо создания дубля;
- верхний список «Модель в этом семействе» только выбирает редактируемый SKU;
- новый файл в блоке параметров по умолчанию получает диаметр и длину выбранной модели;
- при включении «Только для выбранного SKU» фото сохраняется с `sku_specific=true` и не переходит
  на соседние варианты;
- все SKU-фото, включая старые, применяются только к SKU-владельцу и больше не переходят на
  соседние модели;
- приоритет: точное фото SKU → фото варианта по d/D и длине → базовое фото семейства.

## Строгие роли и удаление

- `general` отображается только как «Основное»;
- `top` отображается только как «Вид сверху»;
- `connection` (включая прежние alias `detail` и `connect`) отображается только как «Соединение»;
- отсутствие `general` не компенсируется фотографией `top` или `connection`;
- после удаления роли соответствующая вкладка исчезает, а остальные роли сохраняют свои места;
- если у SKU удалена фотография роли, допускается только семейное фото той же роли, подходящее по
  d/D и длине.

## Метровая труба в категории

- в категориях труб при первом открытии применяется длина `1000 мм`, если она есть среди SKU;
- «Сбросить» возвращает категорию к этому метровому варианту;
- «Все варианты» передаётся отдельным значением `length=all` и действительно снимает фильтр длины;
- другая длина не подставляется скрытно, если метровой SKU нет в выбранной комбинации.

## Карточки совместимых товаров

- технический артикул убран из публичной карточки совместимого товара;
- на его месте показывается подтверждённое назначение из `Product.purpose`, затем краткое описание,
  а при их отсутствии — фактический `product_kind`;
- назначение располагается обычным текстом сразу под названием, без иконки;
- марка и материал внутреннего и наружного контура объединены в один бейдж с одной иконкой;
- при одинаковой толщине она показывается один раз: `AISI 304 нерж. / AISI 304 нерж. — 0,5 мм`;
- при разных толщинах сохраняются оба значения в порядке «внутри/снаружи», например
  `— 0,8/0,5 мм`.

## Хранение данных

У фото варианта в существующем JSON-массиве `media` хранятся области применения:

```json
{
  "media_id": "3ea51098-f20f-4e8a-b26a-df40a6e8bfe1",
  "url": "/media/catalog/categories/example/photo-1-3ea51098.jpg",
  "role": "general",
  "scope": "variant",
  "diameter_keys": ["200/300"],
  "lengths_mm": [500, 1000]
}
```

Базовое фото той же роли имеет `scope: "family"` и пустые списки параметров. В каждой роли такое
фото только одно; его повторная загрузка является заменой базового файла.

`media_id` является стабильным идентификатором конкретной фотографии. Изменение области и удаление
выполняются по нему, поэтому соседние фотографии той же роли не затрагиваются. Для прежних записей
без `media_id` идентификатор вычисляется автоматически и сохраняется при следующем обновлении.

Точное фото модели в `sku_media` получает признак:

```json
{
  "url": "/media/catalog/skus/example/sku-photo-1.jpg",
  "role": "general",
  "scope": "sku",
  "sku_specific": true
}
```

Новая таблица и миграция базы данных не требуются. Каждый файл хранится один раз; выбранные длины
описывают область его применения.

## Отображение уже загруженных фото в админке

- админка объединяет нормализованный список `media` из API с прежним списком
  `extra_attributes.media`, как это делает публичная карточка;
- одинаковые записи объединяются по `media_id`, а для старых записей без идентификатора — по
  области, роли и URL;
- фото варианта, сохранённое для другого диаметра или длины, больше не выглядит удалённым: оно
  остаётся в карточке с пометкой «Сохранено для других параметров»;
- отдельно различаются точное фото SKU, фото по диаметру/длине и базовое фото семейства.
