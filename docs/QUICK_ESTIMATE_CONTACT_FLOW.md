# Контакт перед быстрым расчётом и запрос обратной связи

Изменение подготовлено 2026-11-16. Production обновляется отдельно через `/ship`/`/deploy`.

## Пользовательский сценарий

На последнем шаге `HomeQuickEstimate` одно поле принимает телефон, `@username` или
ссылку `t.me/username`; имя не требуется. Обязательное согласие использует существующий
`PersonalDataConsent`, без заранее установленной галочки. До успешного сохранения
контакта схема, БОМ, стоимость и скачивание PDF не выводятся. Ошибка сети/валидации
оставляет форму открытой; пользователь может повторить отправку.

После открытия результатов порядок: схема → БОМ → стоимость → принятые допущения →
«Связаться со мной» → пояснение предварительного расчёта → PDF и изменение ответов.
Обратная связь запрашивается одним нажатием, без повторного ввода контакта.

## API и хранение

- `POST /api/v1/leads` поддерживает `intent=estimate_access`: обязательны телефон или
  Telegram, действующее согласие и `estimate_json`; имя может отсутствовать.
- Для прежних форм значение по умолчанию — `manager_review`, имя по-прежнему обязательно.
- Структурированная смета и контакт сохраняются в прежнем приватном файловом CRM/storage.
  Новые таблицы и миграции базы не требуются.
- Ответ нового сценария содержит `id` и отдельный `callback_token`. На диске хранится
  только SHA-256 токена; это не менеджерский токен, он не открывает чтение/редактирование БОМ.
- `POST /api/v1/leads/{id}/callback` требует `X-Lead-Callback-Token`. Фиксирует
  `callback_requested_at`, меняет статус того же лида и обновляет карточку CRM.
  Блокировка файла и сохранение до SMTP делают повторные/одновременные нажатия
  идемпотентными. Повтор после потери ответа не создаёт дополнительную заявку/уведомление.
- Получение расчёта: `estimate_received` / «Получил расчёт».
  Просьба связаться: `callback_requested` / «Просит связаться».
- SMTP остаётся опциональным: ошибка письма не отменяет сохранённый запрос в CRM.
- Добавление безымянного расчёта сохраняет ранее известное имя существующего клиента.

## Возврат и аналитика

При переходе из БОМ к товару данные текущего расчёта, контакт и ограниченный callback-токен
сохраняются в `sessionStorage` этой вкладки вместе с прежним снимком. Возврат восстанавливает
доступ к результату и статус обратной связи. Снимки имеют версию 3 и срок 24 часа; старый
публичный формат версии 2 не используется. При изменении ответов/новом расчёте доступ
сбрасывается и сохраняется новый расчёт.

`lead_submitted` и `quick_estimate_contact_sent` отправляются после успешного сохранения
контакта. `solutions_calc_result` — после открытия результата с готовым каталогом,
`solutions_calc_submit` — после принятого запроса обратной связи. Контакты/токены в
параметры Метрики и URL не передаются. Отказ от аналитики сохраняется.

## Проверки

Серверные тесты: `backend/tests/test_quick_estimate_contact.py`, прежние тесты leads,
customers, email, документов, заметок и доступа администратора. Проверяются отсутствие
имени, отказ без согласия/сметы, отдельные права токена, одновременные запросы, сохранение
CRM и поведение при отказе SMTP. Frontend: `quickEstimateLead.test.mjs`, обновлённые
контракты HomeQuickEstimate и целей Метрики; production build и TypeScript.

Локальный браузерный прогон выполнен на 390 и 1280 px с отдельным временным
storage и реальными ответами публичного каталога. Проверены обязательная галочка,
отсутствие результатов до сохранения, ошибки отправки, порядок блоков, потеря ответа
на уже сохранённый callback и повтор без дубля, возврат из товара с тем же лидом,
отсутствие горизонтального переполнения. Тестовые контакты в production не отправлялись.
