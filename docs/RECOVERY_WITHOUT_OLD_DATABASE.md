Ошибок вычисления в этих примерах нет; предупреждения о неполных замерах и

Расширенная проверка: 24 сочетания трёх маршрутов и диаметров
100, 115, 120, 150, 180, 200, 250, 300 мм. В 16 сочетаниях найдены все
запрашиваемые SKU. Ни в одном примере нет ошибки вычисления. В восьми сочетаниях
есть пробелы исходного каталога; цена ненайденного исполнения не подменяется:

| Внутренний диаметр | Через потолок | Через стену, верхний выход | Через стену, задний выход |
| --- | --- | --- | --- |
| 100, 120, 150, 180, 200 | Все SKU | Все SKU | Все SKU |
| 115 | Все SKU | Нет силового хомута Ø215 | Нет силового хомута Ø215 |
| 250 | Нет юбки Ø350 | Нет юбки и силового хомута Ø350 | Нет юбки и силового хомута Ø350 |
| 300 | Нет юбки Ø400 | Нет юбки и силового хомута Ø400 | Нет юбки и силового хомута Ø400 |

Наличие всех SKU не означает, что все позиции имеют цену: исходный режим
«цена по запросу» сохраняется. Подробности — `calculation-check.json` в runtime.
Для проверки полного подбора владелец 4 ноября разрешил временные цены 100 ₽.
Пять отсутствующих типоразмеров добавлены как `[ТЕСТ]`-SKU с артикулами
`RECOVERY-TEMP-*`, неизвестным наличием и меткой `recovery_temporary_price`.
Значения материала/марки тестовых юбок — требуемые существующим BOM поля подбора,
не подтверждение наличия реального исполнения. Прочие неизвестные характеристики
не заполняются. Исторические цены существовавших SKU не изменены.

Правило `priceOnRequest` для «Мастер-флеш» остаётся прежним: оно задано кодом
конфигуратора независимо от цены в каталоге. Код расчёта ради тестовых цен
не изменяется. Отдельный скрипт `tools/recovery_placeholder_prices.py` не входит
в startup и миграции и работает только с изолированной recovery-базой.

Добавить тестовые данные (повторный запуск не создаёт дубликаты), из корня проекта:

```bash
/home/dimohod-recovery-runtime/venv/bin/python tools/recovery_run.py \
  --env-file /home/dimohod-recovery-runtime/recovery.env -- \
  /home/dimohod-recovery-runtime/venv/bin/python tools/recovery_placeholder_prices.py --apply
```

Для отмены заменить `--apply` на `--rollback`. Скрипт сохраняет изменённые
вручную цены/параметры и не удаляет их автоматически. До добавления заглушек
сохранён дамп `backups/catalog-recovered-20261104.dump` в runtime.

Если вернётся старая база, её следует восстановить отдельно, проверить ревизию
Alembic и переключить `DATABASE_URL`. Заглушки не переносятся в возвращённую базу,
а расчётные функции остаются теми же. Для старых клиентских файлов также требуется
соответствующий `MEDIA_STORAGE_DIR`.

## Повторное восстановление

`tools/recovery_run.py` загружает отдельный env-файл. Команда импорта ниже
принципиально принимает только новую пустую БД `dimohod_recovery` на loopback:55432.
Она откажется перезаписывать уже восстановленную базу.

```bash
cd /home/dimohod-recovery/backend
/home/dimohod-recovery-runtime/venv/bin/python ../tools/recovery_run.py \
  --env-file /home/dimohod-recovery-runtime/recovery.env -- \
  /home/dimohod-recovery-runtime/venv/bin/python -m app.db.recover_catalog \
  --price-list /home/dimohod-recovery-runtime/sources/price_list.json \
  --sandwich-prices /home/dimohod-recovery-runtime/sources/50mm.json \
  --media-backup ../backups/catalog-media-20260811-211040-database-backup.json \
  --report /home/dimohod-recovery-runtime/recovery-report.json
```

Порядок: схема до `202608010002` → импорт двух прайсов → оставшиеся миграции →
исходные правила совместимости → восстановление доступных фото с применением
сохранённых правил длины. Ключи `--resume-import` и `--resume-migrations` служат
только для точно проверяемой точки остановки, не для произвольного повторного
импорта. Не выполнять команды `downgrade`, `stamp` или сброс базы ради повтора.

`tools/recovery_check.py` проверяет API и изолированное сохранение SKU;
`tools/recovery_calculation_check.mjs` сопоставляет три примера расчёта с API.
Снимок восстановленной базы и версии Python-зависимостей находятся в runtime.
