# Telegram → Codex для Dimohod Trade и Sunny Rentals

Один личный Telegram-бот запускает локальный Codex CLI в `/home/dimohod-trade` или
`/home/sunny-rentals`. После `/start` или `/projects` пользователь выбирает проект. Для каждого
проекта бот хранит один Codex thread, который сохраняется при переключении моделей, и показывает
прогресс выполнения команд.

## Возможности

- текстовые задачи для Codex;
- голосовые задачи через OpenAI Audio Transcription API;
- фото в Telegram: бот скачивает фото, анализирует его через OpenAI Vision и передаёт анализ в Codex;
- альбомы до 10 скриншотов: бот объединяет их в одну задачу и анализирует как общий сценарий;
- генерация изображений командой `/image описание`;
- отправка файлов из проекта командой `/file path/to/file`;
- приём документов `.md` и `.markdown`, сохранение в uploads и передача файла в Codex;
- отправка файлов по запросу Codex через маркер `[[send_file:path/to/file]]` в финальном ответе;
- сохранение контекста Codex между сообщениями;
- автоматическое восстановление после потерянного Codex rollout: новая сессия получает
  ограниченную историю последних пяти успешных задач и итоговых ответов;
- выбор активного проекта кнопками без запуска второго Telegram-бота;
- выбор профиля Codex: GPT-5.5 high или GPT-5.6 Sol medium;
- автоматический Graphify query перед каждой задачей и структурный контекст в запросе Codex;
- потоковый статус: команды, изменения файлов и финальный ответ;
- `/status`, `/file`, `/image`, `/new`, `/cancel`, `/id`, `/help`;
- подтверждаемые `/commit`, `/push`, `/deploy` и полный `/ship`;
- только один активный процесс Codex на чат;
- `danger-full-access` + `approval_policy=on-request` для Dimohod Trade;
- `workspace-write` для Sunny Rentals;
- первый `/start` в личном чате назначает владельца бота.

Состояние хранится в `.codex-telegram/state.json` и не попадает в Git.

## Конфигурация

Обязательная переменная в корневом `.env`:

```dotenv
CODEX_BOT_TOKEN=telegram-bot-token
```

Для голосовых, чтения фото и генерации изображений:

```dotenv
OPENAI_API_KEY=openai-platform-api-key
OPENAI_API_KEY_2=second-openai-platform-api-key
OPENAI_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe
OPENAI_VISION_MODEL=gpt-5.6-luna
OPENAI_IMAGE_MODEL=gpt-image-2
OPENAI_IMAGE_SIZE=1024x1024
OPENAI_IMAGE_QUALITY=medium
```

Необязательные настройки:

```dotenv
# Отключает автоматическое назначение первого владельца и разрешает указанные ID.
CODEX_BOT_ALLOWED_USER_IDS=123456789

# Если codex отсутствует в PATH. Production unit использует launcher,
# который сам находит актуальный бинарник VS Code-расширения после обновлений.
CODEX_BOT_CODEX_BINARY=/absolute/path/to/codex

CODEX_BOT_MAX_WORKERS=2
```

`OPENAI_API_KEY` — ключ OpenAI Platform API, а не Telegram-токен и не пароль ChatGPT.
Бот автоматически обнаруживает `OPENAI_API_KEY_2`, `_3` и последующие ключи. Активный ключ
выбирается кнопками после `/start` или командой `/apis` и сохраняется для Telegram-чата. Если
OpenAI возвращает ошибку исчерпанной квоты (`insufficient_quota` или billing/usage limit), бот
переключается на следующий ключ и повторяет операцию. Временный rate limit и сетевые ошибки не
переключают ключ, чтобы не маскировать сбой.

## Использование в Telegram

```text
/file PROJECT_CONTEXT.md
```

Отправит файл из проекта. Путь должен быть внутри `/home/dimohod-trade`.

```text
/image фотореалистичный рендер сэндвич-трубы дымохода 115/200 из нержавейки
```

Сгенерирует изображение через OpenAI и отправит его в чат.

Если отправить боту фото с подписью, бот сохранит его в `.codex-telegram/uploads/`,
сделает визуальный анализ и передаст Codex подпись + описание фото как контекст задачи.

## GitHub и deploy

Для Dimohod Trade Codex запускается с `--sandbox danger-full-access` и
`--ask-for-approval on-request`, поэтому процесс имеет прямой доступ к Docker daemon. Sunny
Rentals сохраняет режим `workspace-write`. Подтверждаемые Git/deploy-команды бота остаются
доступны как безопасный стандартный путь публикации:

```text
/commit сообщение commit
/publish сообщение commit
/push
/deploy
/ship сообщение commit
```

Каждая команда сначала показывает preview с кнопками **«Подтвердить»** и **«Отмена»**. Реальное
действие запускается только после нажатия кнопки в течение пяти минут.
`/push` сначала выполняет `git add -A` для всех изменений активного проекта,
создаёт commit при наличии изменений и отправляет ветку в GitHub. `/publish` и
`/ship` также включают всё рабочее дерево, в том числе файлы вне последней задачи.
Новые файлы, изменения и удаления сохраняются. Отдельная `/commit` может сохранять
явно заданный набор файлов. Секреты и runtime-данные исключены.

На текущем VPS Дымоходы используют `/home/dimohod-recovery` и ветку
`recovery/catalog-without-old-db` (переменные CODEX_BOT_PROJECT_ROOT и DIMOHOD_GIT_BRANCH).
`/deploy` запускает `deploy/native-deploy.sh` → `dimohod-deploy.service`: сборка
отдельного релиза, резервная копия, штатные миграции существующей базы,
переключение systemd-сервисов и проверка готовности. При ошибке запуска возвращается
предыдущая версия приложения. Данные storage и PostgreSQL не перезаписываются.
Старый удалённый Beget deploy отключён по умолчанию.
Подробности и перенос: `docs/PRODUCTION_VPS.md`.

Настройки других проектов сохраняются отдельно; изменение всех файлов при push
также применяется только к выбранному проекту.

Graphify хранит отдельный граф в каждом проекте. Перед запуском Codex бот выполняет ограниченный
`graphify query` по тексту задачи и добавляет найденные узлы как навигационный контекст. Исходные
файлы остаются источником истины. Git post-commit hook обновляет кодовую часть графа без фонового
процесса и дополнительного постоянного потребления памяти.

Те же операции распознаются в обычном тексте и после транскрибации голосового: «закоммить»,
«запушь», «задеплой», «сделай релиз». Для составной команды вроде «исправь карточку, запушь и
задеплой» Codex сначала меняет проект, после чего бот показывает release-preview и ждёт
подтверждение.

Preview также можно подтвердить или отменить голосом/текстом: «подтверждаю, запускай» либо
«отмени релиз». Одно короткое «да» намеренно не запускает опасные операции.

Финальные ответы Codex отправляются с Telegram Markdown-разметкой. Если конкретная разметка
оказалась несовместима с Telegram, бот автоматически повторяет сообщение как обычный текст.

После каждой успешной задачи, которая изменила разрешённые файлы, бот показывает кнопки:

- **«🚀 Пуш и деплой»** — тесты → commit → push → deploy;
- **«➡️ Продолжить»** — оставить изменения локально и ждать следующую задачу.

Для ответов без файловых изменений эти кнопки не показываются. Перед push в commit
войдут все изменения проекта. Исключаются `.env` и его рабочие варианты в любых
подкаталогах, credentials, SSH-ключи, дампы БД, runtime бота, `storage/leads/`,
`storage/customers/` и другие приватные каталоги проекта. Шаблоны `.env.example`
можно сохранять; цены и исходники конфигуратора входят в обычный push.

API-ключ для голосовых/изображений на текущем VPS: `/home/codex-bot/.env`,
строка `OPENAI_API_KEY=...`; после изменения —
`systemctl restart dimohod-codex-bot.service`. Файл имеет права 0600 и не входит
в Git. Авторизация самого Codex CLI хранится отдельно; текущий ChatGPT login
сохраняется, наличие ключа для медиа не является командой сменить способ оплаты CLI.

## Запуск

Codex CLI должен быть авторизован под тем Linux-пользователем, который запускает бота.

```bash
cd /home/dimohod-trade
python3 -m tools.codex_telegram_bot.bot
```

После запуска сразу отправьте боту `/start` в личном чате. Первый пользователь станет владельцем.
`/start` показывает отдельные кнопки проекта и модели; повторно открыть их можно командами
`/projects` и `/models`.
Для production лучше заранее задать `CODEX_BOT_ALLOWED_USER_IDS`.

Бот является внешним каналом управления приватным репозиторием: авторизованный Telegram-пользователь
сможет менять файлы и получать фрагменты содержимого обоих проектов. Не добавляйте бота в группы, не
передавайте его токен и задайте `CODEX_BOT_ALLOWED_USER_IDS` до постоянного запуска.

## Проверка

```bash
python3 -m unittest tools.codex_telegram_bot.test_bot
```

## Запуск через systemd

Unit-файл: `deploy/dimohod-codex-bot.service`. Код бота установлен отдельно
в `/home/codex-bot`, рабочие проекты задаются отдельно. Релиз запускается через
`deploy/dimohod-deploy.service`, поэтому бот не нуждается в прямой записи в `/etc`.
Не запускайте второй экземпляр с тем же Telegram token.

Если при `/ship` или `/publish` новых разрешённых изменений нет, commit пропускается, а pipeline
продолжает push/deploy. Отдельная `/commit` по-прежнему сообщает об отсутствии изменений.
